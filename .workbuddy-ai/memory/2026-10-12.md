## multi-grok-state — Grok CLI 多帳號管理工具（Node.js + chalk）

Workspace: `D:/CODE/MultiGrokState`

### 目標
參考 `C:\Users\chbon\.grok` 的 auth.json 結構，做一個 Node.js CLI 管理多個 Grok 帳號的使用量，
提供 `/login`、`/logout`、`switch`、`usage` 指令，原理是複製 auth.json 改名為 `<帳號>_auth.json`。

### 關鍵研究結論
- `~/.grok/auth.json` 是 **map 結構**，key 為 scope 字串 `https://auth.x.ai::<client_id>`，
  value 含 `key`(access token JWT) / `refresh_token` / `email` / `user_id` / `expires_at` /
  `oidc_client_id` / `oidc_issuer`。Grok CLI 會 **hot-reload** 此檔，換檔即換帳號、免重啟。
- OAuth client_id: `b1a00492-073a-47ea-816f-4c329264a828`；issuer `https://auth.x.ai`。
- **額度查詢端點**：`GET https://cli-chat-proxy.grok.com/v1/billing?format=credits`（週）
  與 `GET .../v1/billing`（月）。
  Headers: `Authorization: Bearer <token>`、`Accept: application/json`、
  `x-grok-client-mode: cli`。
- **重要**：`auth.json` 裡的 token 常常已過期，直接打會回 **401**
  `Invalid or expired credentials (... upstream=PermissionDenied)`。
  必須先 refresh：`POST https://auth.x.ai/oauth2/token`
  with `grant_type=refresh_token&refresh_token=<rt>&client_id=<cid>`，
  再帶新 token 重打 → 200。
- 週報表欄位：`config.creditUsagePercent`（**方案無上限時此欄位不存在**）、
  `config.currentPeriod.{type,start,end}`、`config.productUsage[].{product,usagePercent}`、
  `onDemandCap/onDemandUsed/prepaidBalance`（皆為 `{val:n}` 包裝）、`isUnifiedBillingUser`。
- 月報表欄位不同：`config.{monthlyLimit,used,history[]}` → 需自行用 used/limit 推算百分比。

### 第三輪：本地測試harness（`test/run.js`，`npm test`）

1. **`-k` 短旗標沒作用**（`src/cli.js` cmdLogout 只認 `--keep`）→ 已補 `|| argv.includes('-k')`。

   並在 `src/cli.js` 的 `list --usage` 與 `usage` 兩處接上 callback。
   修完後真實帳號的 `testacct_auth.json` 的 `expires_at` 從 2026-10-02 更新為當日 → 確認生效。
3. 測試 harness 自身的坑：`spawnSync` 在 Windows 會 **EBUSY**（重入同一 node binary）

   導致測不到 401 路徑 → 改成 `stale.*` 一律回 401 才真正驗證到 refresh 流程。

**教訓**：offline mock 測試能抓到真實 API 測不到的 bug（因為真 token 剛好過期會 mask 掉持久化問題）。
